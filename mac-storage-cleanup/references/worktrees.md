# Git worktrees

1. Start from ordinary repositories or known worktree roots and read `git worktree list --porcelain -z`. Use registered checkouts rather than a folder name alone. A directory with its own independent Git common dir can be a separate project, even under a directory named `worktrees`. Protect each repository's primary checkout, any branch checkout the user specifically wants kept, and nested independent repos. Preserve attached/managed worktrees using the host's supported lifecycle tooling when applicable. If a managed entry cannot be handled within the requested recovery behavior, explain the limitation instead of bypassing its protection.
2. If the age rule is ambiguous, clarify whether it applies to each checkout or an entire project. Use recent source file creation and modification, Git HEAD/reflog activity, and generated-file writes as appropriate. Commit date alone misses fresh checkouts and uncommitted changes. Access time alone does not prove user activity. For active checks include process working directories, open files, and Docker paths used inside bind mounts. For a container with a broad project-root mount, check the actual working directories and open paths inside the container before classifying the mounted worktrees.
3. Separate two operations. **Clear generated files** using the exact project cache/dependency paths after checking tracked and local-only content. **Remove a checkout** through Git or its manager only after validating it is linked, within scope, unlocked, and not part of a live build or Git operation. Before removing dirty or detached worktrees, inspect tracked edits, untracked/ignored files, and commits that would lose their reference. Save recoverable work if agreed and supported, or follow explicit authorized discard/no-backup instructions. Avoid force against a locked worktree, independent nested repo, or active process.
4. Discover and validate read-only first, then recheck immediately before changing paths. Use normal `git worktree remove` for ordinary linked worktrees. Treat forced removal of dirty work as explicit destructive scope. Never substitute recursive removal plus blanket pruning. Avoid global `git worktree prune` for a checkout that might be on a disconnected or moved volume. Verify both paths and the worktree registry after removal, and independently measure reclaimed disk space.
